# STM32F407 编码器触发 ADC 采集与 USB CDC 上传固件

基于 STM32F407 的裸机固件：以**编码器信号**作为硬件触发源驱动 ADC 采样，采样数据经**环形队列**缓冲后由 **USB CDC 虚拟串口**上传至上位机；同时利用每转一次的 **Z 相脉冲**测量转速，转速通过 **USART1 调试遥测**输出（USB 数据流不再插入转速帧）。

工程采用 `APP → SERVICE → PLATFORM ← IMPLEMENT → VENDOR` 的分层多态架构，业务逻辑与 STM32 硬件完全解耦。

---

## 功能特性

- **编码器触发采样**：PA5（TIM2_CH1）编码器上升沿触发 ADC1 转换，采样率与转速天然同步
- **DMA 环形搬运**：ADC1 → DMA2 双缓冲（1024 半字），半满/满中断批量提交，CPU 开销极低
- **两级异步缓冲**：驱动层 DMA 环形缓冲 + 服务层 16 KB 字节环形队列，解耦采样速率与 USB 发送速率
- **背压保护**：队列水位过高或 USB 端点忙时自动 `pause` 采样，恢复后 `resume`，并统计丢样与忙次数
- **Z 相测速**：PB12 每转一个脉冲，TIM5（1 MHz）记录周期，换算转速，超时自动归零
- **上位机命令控制**：`O\0` 启动采集、`C\0` 停止采集；`E\0`/`D\0` 控制 PB11 使能引脚
- **串口调试遥测**：USART1 每秒输出一行 `D ...` 运行指标（转速、DMA 中断、队列水位、错误计数等）；USB 数据流中**不再插入转速帧**，图像数据保持连续

### 引脚分配

| 引脚 | 功能 | 说明 |
|---|---|---|
| PA2 | ADC1_IN2 | 模拟量输入，采样时间 56 周期 |
| PA4 | 相位 A | GPIO 输入（编码器 A 相） |
| PA5 | 相位 B / 触发 | TIM2_CH1 单边沿输入，**每个上升沿触发一次 ADC** |
| PB12 | Z 相 | 每转一个脉冲，用于周期测速 |
| PA11 / PA12 | USB OTG_FS | 全速 USB，CDC 虚拟串口 |
| PA9 / PA10 | USART1 | 调试串口，115200-8-N-1 |

### 定时器用途

- **TIM2**：编码器脉冲输入与 ADC 外部触发源
- **TIM5**：72 MHz / 72 = **1 MHz** 自由运行计数器，为 Z 相边沿打时间戳

## 软件架构

```
        ┌──────────────────────────────────────────┐
        │  USER/main.c           → app_main()      │  启动入口
        ├──────────────────────────────────────────┤
        │  APP/app_main.c        → 主循环编排      │  应用层
        ├──────────────────────────────────────────┤
        │  SERVICE/adc_stream_service.c            │  服务层（业务状态机）
        │    · 收发环形队列  · 命令解析  · 转速帧  │
        ├──────────────────────────────────────────┤
        │  PLATFORM/platform_*.h                   │  平台抽象层（仅接口）
        │    adc_stream / byte_stream / usb_device │
        │    debug_uart / board                    │
        ├──────────────────────────────────────────┤
        │  IMPLEMENT/impl_*.c                      │  平台实现层（适配）
        │    组装板级 platform 对象、转发中断      │
        ├──────────────────────────────────────────┤
        │  VENDOR/vendor_*.c                       │  驱动层（寄存器级）
        │    GPIO / TIM / ADC / DMA / USB CDC      │
        └──────────────────────────────────────────┘
```

**依赖方向**：上层只依赖 `platform_*.h` 中声明的抽象对象（`ops` 函数表 + `impl` 私有指针），不包含任何 `IMPLEMENT/` 或 `VENDOR/` 头文件。更换硬件方案时，只需替换 IMPLEMENT/VENDOR 两层。

| 层 | 目录 | 职责 |
|---|---|---|
| 应用层 | `APP/` | 初始化服务、主循环调度、串口调试遥测 |
| 服务层 | `SERVICE/` | ADC 数据流状态机、队列管理、命令解析、转速帧上报 |
| 平台抽象层 | `PLATFORM/` | ADC 采样流 / 字节流 / USB 设备 / 调试串口 / 板级对象集合的纯接口定义 |
| 平台实现层 | `IMPLEMENT/` | 把抽象落到 STM32 硬件，组装板级对象，转发中断回调；含 printf → USART1 重定向 |
| 驱动层 | `VENDOR/` | 寄存器级外设驱动与 USB CDC 协议栈封装 |
| 板级支持 | `SYSTEM/` | SysTick 延时、位带 GPIO 宏定义 |
| 启动与 CMSIS | `CORE/`、`USER/` | 启动汇编、向量表、中断服务例程、系统时钟初始化 |
| 外设库 | `FWLIB/` | ST 标准外设库（裁剪后按需参与编译） |
| USB 协议栈 | `USB/` | USB OTG 驱动 + CDC 类实现 + 用户配置 |

## 数据通路

```
编码器脉冲 ──▶ TIM2 触发 ──▶ ADC1 ──DMA──▶ 驱动层双缓冲
                                              │ 半满/满中断
                                              ▼
                        服务层 ADC 队列（16 KB 环形）
                                              │ poll 批量取 512 字节
                                              ▼
                                  USB CDC 发送端点 ──▶ 上位机

Z 相脉冲 ──▶ TIM5 时间戳 ──▶ 周期换算 ──▶ 转速（USART1 D 行，500 ms 周期）
```

- 采样中断只做「入队」，不做任何耗时操作
- 主循环 `poll` 每次最多搬运 512 字节到 USB 发送环
- USB 数据流只包含 ADC 采样字节，不再插入转速帧；转速只走 USART1 调试口

## 通信协议

USB CDC 虚拟串口，波特率设置对全速 USB 无效（任意值均可）。

### 上位机 → 设备（命令，2 字节）

| 命令 | 字节序列 | 作用 |
|---|---|---|
| 启动采集 | `4F 00`（`'O'` + `\0`） | 启动 TIM2 → ADC → DMA 采集，清空本地发送队列 |
| 停止采集 | `43 00`（`'C'` + `\0`） | 停止触发，冲刷 DMA 残余数据，队列发空后转入停止态 |
| 使能 PB11 | `45 00`（`'E'` + `\0`） | PB11 输出高电平（使能新板 3 V 电源轨） |
| 失能 PB11 | `44 00`（`'D'` + `\0`） | PB11 输出低电平（失能） |
| 打开 FIR | `46 00`（`'F'` + `\0`） | 仅 `ADC_FIR_ENABLE=1` 时有效 |
| 关闭 FIR | `52 00`（`'R'` + `\0`） | 仅 `ADC_FIR_ENABLE=1` 时有效；RAW 旁路 |

命令需以 `0x00` 结尾才会执行；未等到结尾字节时暂存，收到非命令字节则丢弃。
PB11 上电默认高电平（沿用原板级初始化行为）。

重复发送 `4F 00` 在采集中是**幂等**的：不会清空队列、不会复位 FIR、不会清零统计。
需要重新开始一次采集时，先发 `43 00` 停止，再发 `4F 00` 启动。

### 设备 → 上位机：ADC 数据流

启动采集后持续输出的**原始采样字节流**，无帧头、无分隔，连续不断：

```
[采样0][采样1][采样2]...
```

每个字节对应一次编码器触发产生的 ADC 采样值。

### 转速

**USB 数据流中不再发送 `A5 5A 52 04` 转速帧**。这样上位机收到的每个字节都是
ADC 采样值，不会因为 9 字节帧插入而出现行错位。

转速仍在 USART1（PA9/PA10，115200-8-N-1）每秒输出的 `D ...` 行里：

```
D t=... st=2 rpm=1500 ... z=8 zp=40000 ...
```

超过 12000 rpm 或 Z 相超时，`rpm` 报 0。

## 调试输出

USART1（PA9/PA10，**115200-8-N-1**）每秒输出一行运行遥测：

```
BOOT uart=115200 service=0 usb=data pa5=trigger pa2=adc pb12=z idle=wfi
EV START
D t=1234567 st=2 rpm=1500 h=42 f=21 n=86016 sn=86016 ... q=0 pk=3 ub=0 ue=0 p=0 rs=0 dr=0 mn=12 mx=241 ls=137 ov=0 z=8 zp=40000 hw=63
```

关键字段：

| 字段 | 含义 |
|---|---|
| `st` | 服务状态（0=未初始化 1=停止 2=采集中 3=暂停 4=错误） |
| `rpm` | 当前转速 |
| `h` / `f` | DMA 半满 / 满中断计数 |
| `n` | 已产出的采样字节数（DMA 提交给 service 的数量） |
| `sn` | 已成功写入 USB 发送环的 ADC 字节数 |
| `q` / `pk` | 当前 / 峰值队列水位 |
| `ub` / `ue` | USB 忙返回次数 / 连续忙次数 |
| `p` / `rs` | 采样暂停 / 恢复次数 |
| `dr` | 丢弃采样字节数 |
| `mn` / `mx` / `ls` | ADC 最小值 / 最大值 / 最新值 |
| `ov` | ADC 溢出次数 |
| `te` / `de` / `fe` | DMA 传输 / 直接 / FIFO 错误计数 |
| `z` / `zp` | Z 相中断次数 / 最近周期（µs） |
| `hw` | 硬件状态位掩码 |

> `n` 只表示 ADC 已经产出并交给 service 的字节数；`sn` 才是真正写进 USB 发送环的字节数。
> 如果 `n` 持续增长而 `sn` 不增长，说明数据卡在 service→USB 这一段（例如队列/pending 状态异常）。

> `idle=wfi` 为预留的 Cortex-M4 Sleep 低功耗路径，当前在 `app_main.c` 主循环中**已注释**（USB 唤醒调试期间关闭）。

## 上位机

`HOST/` 目录提供本地串口桥接上位机（Python pyserial + 单页界面）：

- 真正的 COM 下拉框（直接选 COM3/COM5…），端口占用/不存在有明确提示
- 实时 ADC 波形（默认 10 ms 窗口，支持暂停、缩放、拖动、游标读数）
- 转速仪表与 120 s 趋势、8192 点 FFT 频谱与主要频率成分
- 自动剥离 `A5 5A 52 04` 转速帧、估计采样率、识别削顶/丢样等异常
- 可选解析 USART1 的 `D ...` 调试遥测
- 连接诊断：接收字节数、发送命令、原始 hex 字节

双击 `HOST/start.bat`（需要 Python 3 + pyserial 与 Edge/Chrome）。数据口选
**0483:5740** 的 COM，调试口选 USART1 的 USB-TTL。详见 `HOST/README.md`。

## FIR 低通滤波（新增）

采集数据在 SERVICE 层发送前经过一个 Q15 低通（等效说明书 129 抽头）：

- **一键开关**：`SERVICE/adc_fir.h` 的 `ADC_FIR_ENABLE`。
  - `1`：编译 FIR 和运行时指令，上电默认**开**（滤波）；
  - `0`：FIR 和 `F`/`R` 指令一起编译掉，完全回到旧行为；已核对关闭时
    RO/RW 尺寸与改动前一致（30372 / 55760 字节）。
- **运行时指令**（与 `O`/`C` 同一套 `X 00` 格式）：
  - `46 00`（`'F'` + 0x00）：打开 FIR；
  - `52 00`（`'R'` + 0x00）：关闭 FIR，RAW 旁路，输出与未加滤波时逐字节一致；
  - `4F 00` / `43 00`：采集开始 / 停止，语义不变。
  - 指令在下一个发送块生效；切回 FIR 时会清空历史并重新预热。
- **参数**：fs=200 kS/s、fc=15 kHz（−6 dB，50 r/s 下 300 次/转）、群延迟 64 样本
  （5.76°，表现为整幅图沿扫描方向平移 64 点）。
- **为什么是 130 项**：CMSIS `arm_fir_init_q15` 在 Cortex-M4 要求偶数抽头。
  129 抽头会在时域冲激响应末尾补 1 个 0；CMSIS 系数按时间反序存放，所以 C 数组
  首元素是 0，频响和 64 样本群延迟不变。详见 `SERVICE/adc_fir_coeffs.h` 顶部注释。
- **新增文件**：`SERVICE/adc_fir.c/.h`、`SERVICE/adc_fir_coeffs.h`、`CMSIS_DSP/`；
  系数生成与校验见 `TOOLS/gen_fir_coeffs.py`。
- **启动过渡**：每次开始采集时用第一个样本预热延迟线，前约 128 点仍是过渡段；
  如果成像对首圈敏感，建议上位机丢弃每次采集的第一圈（或前 128 点）。
- **注意**：USB 数据流中的 `A5 5A 52 04` 转速帧本次**未改动**。真实上位机不剥离它，
  会把 9 字节当成 9 个样本；该兼容性问题需后续单独处理。
