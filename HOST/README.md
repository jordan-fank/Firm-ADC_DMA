# 编码器触发采样 · 智能分析上位机

配合本仓库 STM32F407 固件使用，替代串口助手，把 USB CDC 上的原始 hex 字节流变成：

- 实时 ADC 波形（示波器式 min/max 包络、游标读数、暂停/缩放/平移）
- 峰峰值、均值、真 RMS、AC RMS、过零频率、削顶统计
- 转速仪表 + 120 s 转速趋势（自动剥离 `A5 5A 52 04` 转速帧）
- 8192 点 FFT 频谱与主要频率成分自动标注
- 可选的 USART1 调试口遥测解析与健康告警
- 一键发送固件协议中的 `O\0` / `C\0` 启停命令
- **连接诊断**：显示实际选中的 COM 口、接收字节数、发送命令、原始 hex 字节

## 为什么是本地桥接

浏览器自带的 Web Serial 有两个硬限制：

1. 不能按 COM 号选择，只能弹浏览器的设备选择器；
2. 设备被串口助手占用时无法打开，而且错误提示不直观。

因此本版本改成本机 Python 桥接：`bridge.py` 用 pyserial 打开 COM 口，页面通过
`http://127.0.0.1:8765/api/*` 收数据。这样就可以直接按 **COM3 / COM5** 选择，
端口不存在、被占用、读取失败都会明确显示在“连接诊断”里。

## 快速开始

1. 双击 **`start.bat`**（会启动 `bridge.py` 并打开浏览器）。
2. 关闭正在占用串口的**串口助手**。
3. 在页面顶部 **数据口** 下拉框选择 STM32 数据口：
   - 通常显示为 `COM3 · USB 串行设备`，并带 **（STM32）** 标记（VID:PID = `0483:5740`）；
   - 若不确定，打开设备管理器 → 端口，拔插板子看哪个 COM 消失/出现。
4. 点 **连接** → **开始采集** → 转动编码器 / 电机。
5. 可选：**调试口** 选择 USART1 对应的 USB-TTL（常见是 `COM5 · USB-SERIAL CH340`，或 J-Link CDC UART），点调试口的 **连接**。

> 数据口和调试口是两个不同的 COM。数据口是本固件的 USB CDC（`0483:5740`）；
> 调试口是 USART1 经板载 USB 转串口 / J-Link 出来的口。

## 环境要求

- Windows 10/11
- Python 3 + pyserial（`pip install pyserial`）
- 浏览器：Edge / Chrome（其他现代浏览器也可，页面本身不再依赖 Web Serial）

首次运行如果 start.bat 窗口提示找不到 Python，请确认 `python` 在 PATH 中；
也可以手动在 `HOST` 目录执行：

```
python bridge.py
```

## 连接诊断怎么用

页面底部的“连接诊断”会实时显示：

| 项 | 说明 |
|---|---|
| 数据口 | 实际打开的 COM 与描述 |
| 接收 / 解析 | 收到的原始字节数 / 解析出的 ADC 样点数 / 转速帧数 |
| 最近发送 | 点“开始/停止”时实际发出的 `4F 00` / `43 00` |
| 原始字节 | 最近 192 个原始字节的 hex |

排查顺序：

1. **一直显示“尚未收到字节”**：串口打开了但设备没有产生数据。先确认编码器在转；
   若串口助手此时能看到数据，说明选错了口（数据口应是 `0483:5740` 那个）。
2. **原始字节里出现 `44 20 74 3D`**：这是 ASCII `D t=`，说明选的是 USART1 调试口，
   不是 ADC 数据口。请换 `0483:5740` 的 COM。
3. **点连接就报“拒绝访问 / 被占用”**：先关闭串口助手、其他上位机或调试软件。
4. **下拉框没有你的 COM**：点“刷新”；仍没有则检查驱动/设备管理器。

## 数据是怎么被解析的

固件把两类数据混在同一个 USB CDC 流里：

| 数据 | 格式 |
|---|---|
| ADC 采样 | 8 bit 原始值，无帧头、连续不断，每个字节 = 一次编码器触发的采样 |
| 转速帧 | `A5 5A 52 04` + uint32 小端 RPM + 前 8 字节累加和，共 9 字节 |

上位机对字节流做状态机扫描：

1. 找到 `A5` 后检查后续 `5A 52 04`；
2. 校验 9 字节累加和，并限制 RPM ≤ 12000；
3. 通过校验则作为转速帧剥离，否则连同候选字节一起按 ADC 采样值保留；
4. 跨 USB 包的半帧会被缓存到下一次拼接。

因此波形里不会混入转速帧，也不会因为 ADC 数据中偶然出现 `A5` 而丢样（除非 9 字节
恰好同时通过校验和 RPM 范围校验，概率极低）。

### 时间与频率换算

ADC 由编码器上升沿触发，采样率不是固定值：

```
采样率 ≈ RPM × 4000 / 60        （1500 rpm → 100 kSa/s）
```

- 波形时间轴与 FFT 频率轴优先使用 RPM 推算的**编码器触发速率**（转速帧 2.5 s 内有效）；
- 固件在 USB 背压时会暂停 ADC，字节**送达速率**可能低于触发速率，因此它只作为后备与交叉校验；
- 面板同时显示「实测送达速率」与「RPM 推算采样率」，偏差超过 10% 会提示 USB 背压或测速异常；
- 暂停显示时频率轴冻结在暂停时刻使用的速率；
- 转速波动会导致非等间隔采样，频谱会略微展宽，界面会给出提示。

## 界面说明

- **数据口 / 连接**：COM 下拉 + 连接/断开；连接成功后发送 `O\0` 需点“开始采集”。
- **开始/停止采集**：分别发送 `4F 00` / `43 00`，固件不回 ACK。界面通过是否收到数据
  推断「启动中 / 等待触发 / 采集中 / 停止中 / 已停止」；无数据时会提示转动编码器。
- **暂停显示**：只冻结画面，串口仍在接收；滚轮缩放、拖动平移、双击继续。
- **自动量程**：根据可见窗口自动调整 Y 轴；取消勾选后固定 0–255。
- **数据流**：实测送达速率、RPM 推算采样率、累计样点、有效帧、伪帧数等。
- **调试遥测**：解析 USART1 的 `D t=… st=… rpm=… q=…` 行，显示队列水位、
  丢样、USB 忙、ADC 溢出、DMA 错误等，并在异常时给出告警。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 数据口下拉框为空 | 点“刷新”；确认板子已上电、USB 线是数据线；设备管理器里能看到 COM |
| 连接时报“拒绝访问/被占用” | 关闭串口助手、J-Link 串口终端、其他上位机后重试 |
| 已连接、已开始，但接收一直是 0 B | 编码器未转动 / PA5 没有脉冲；或选错了 COM（看原始字节判断） |
| 原始字节是 `44 20 74 3D ...` | 选的是 USART1 调试口，改选 `0483:5740` 的数据口 |
| 有原始字节但波形不动 | 把“原始字节”和页面状态发我；可能是解析/状态推断问题 |
| 停止后仍有短暂数据 | 固件收到 `C\0` 后会先冲刷队列残余数据，属正常现象 |
| 网页提示“桥接未运行” | 双击 start.bat；若窗口报错，把报错内容发我 |
